Java RapidAPI Taobao Cálculo de Importação

Acessar o programa →

💳 Cadastro e "assinatura" são simulados — nenhum pagamento real é cobrado, é só uma demonstração do fluxo. Por rodar em hospedagem gratuita, o primeiro acesso pode levar de 30 a 50 segundos pra "acordar" o servidor.

O problema

Quem revende produtos importados precisa monitorar manualmente o que está em alta no Taobao — um processo lento e repetitivo que consome tempo que poderia ir pra atender clientes. E mesmo achando um produto em alta, ainda falta saber se ele realmente vale a pena depois de imposto, frete e taxa de marketplace.

A solução

Uma aplicação web com backend em Java que consulta a API do Taobao (via RapidAPI), traduz automaticamente o termo de busca pra chinês e os títulos dos produtos de volta pra português. Pra cada produto encontrado, o frontend calcula na hora a simulação de importação pro Brasil — Imposto de Importação, ICMS, frete estimado, custo total desembarcado, preço de venda sugerido no Mercado Livre/Shopee (já descontando taxa de marketplace) e o lucro líquido estimado por unidade. A ideia é transformar uma lista de produtos em alta numa lista de oportunidades já filtradas pela viabilidade real do negócio.

Decisões técnicas

Optei por Java pela familiaridade com a linguagem e por controle mais direto sobre chamadas HTTP e estruturas de dados. O maior desafio foi o gerenciamento de cache e limites de quota da API — cada chamada tem custo, então implementei um cache em memória com expiração de 6 horas e uma lógica de retry que insiste de novo só em caso de erro de rede, nunca quando a API responde 429 (cota estourada), pra não desperdiçar chamadas à toa. Quando a cota esgota mesmo assim, um fallback com dados de exemplo assume a resposta, pra manter a experiência utilizável em vez de quebrar a tela. Também adicionei cadastro, login e um checkout simulado (sem gateway de pagamento real) que emite um token de acesso por usuário — o que deu ao projeto uma cara mais próxima de um produto SaaS do que de um script.

Status e aprendizados

Projeto em desenvolvimento ativo. Tem me ensinado bastante sobre estratégias de cache, controle de rate limit, design de fallback pra manter resiliência quando uma API de terceiros falha, e sobre como pensar em produto (autenticação, experiência do usuário) além da lógica pura de automação — problemas que exercício de curso não ensina.
